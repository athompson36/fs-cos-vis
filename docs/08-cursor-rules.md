# Expanded Cursor Rules

## Testing (Rule #1)

When testing, fix and verify all errors and warnings before moving on to the next step. Run the full test suite for the app scheme after substantive changes; resolve build errors, test failures, and new compiler warnings before continuing.

## Always preserve
- the music-first experience
- fast scene navigation
- strong visual identity
- modularity
- documentation clarity

## When generating code
- keep models explicit
- keep managers separated
- keep rendering parameters grouped logically
- leave hooks for future multiple output displays
- avoid fake implementations hidden as complete work

## When generating UI
- include BPM somewhere visible
- make previous/next scene controls obvious
- provide a clean performance mode
- use cosmic polish without becoming cluttered

## When generating visuals
- support both standalone liquid light and hybrid mode
- use palettes, not arbitrary colors everywhere
- think in layers and passes
